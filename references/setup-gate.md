# 首次安装与配置入口

本入口先于口播分析和制作。目标是让接收方知道自己能否继续、缺什么、是否愿意配置；不是要求用户自行排查，也不是见到缺项就自动安装。

## 先判定平台模式

在运行本地预检前先读 [平台兼容与接入](platform-compatibility.md)，确认当前环境属于 `FULL_PRODUCTION`、`PROJECT_HANDOFF` 或 `PLANNING_ONLY`。只有 `FULL_PRODUCTION` 才能把下方全部本地依赖视为成片前置条件。其余模式继续完成允许范围内的规划或工程移交，并明确阻塞点；不要在没有终端的平台反复尝试运行脚本。

## 1. 自动发现路径

- Skill根目录以当前读取的SKILL.md/脚本真实位置为准，不复制作者机器路径，不假设当前终端就在Skill目录。
- Codex技能根目录优先接收方CODEX_HOME下的skills，否则用户目录下.codex/skills；兼容项目.agents/skills、用户.agents/skills。非Codex宿主用其实际已注册目录，不强改到Codex目录。
- 工作目录取当前用户项目或用户指定目录，不把视频工程写到技能安装目录。素材相对路径相对工作目录解析。检测路径存在、可读、工作目录可写；中文/空格路径使用结构化参数或正确引号，不拼接shell命令。
- 找不到素材时问文件位置；路径错误不等于缺软件，不能以重装解决。没有具体素材时可完成基础环境检查，输入可读性等到素材到达再核对。
- Node尚未可用：Windows用Get-Command node、npm、ffmpeg、ffprobe，macOS/Linux用command -v。检测结果不自动安装，给配置方案后询问。Node可用才运行脚本。

```sh
node <Skill根目录>/scripts/preflight.mjs --workspace <工作目录> --input <口播文件>
```

预检默认只做本机只读探测，不调用npx自动下载安装，不发网络请求、不试用付费额度。输出中不包含密钥和完整环境变量。报告仅发送版本、路径、状态与原因。

## 2. 分层检查，不用“有文件”替代“可用”

| 项目 | 检查方法 | 缺失时影响 |
|---|---|---|
| Node.js 22+ / npm | 命令实际运行和版本 | 本包工具/HF依赖安装 |
| ffmpeg / ffprobe | 命令实际运行 | 媒体检测、转码、成片解码 |
| HyperFrames | 项目本地包或PATH里已有CLI实际运行--version | HF项目制作与渲染 |
| hyperframes-core / hyperframes-cli技能 | 宿主可读的SKILL.md；读内容确认技术合同可用 | 正确实现与CLI操作 |
| 渲染浏览器 | 按当前HF帮助运行本地doctor/浏览器检查，读取实际结果 | HTML渲染；Chrome存在不代表HF能启动它 |
| 词级对齐 | 当前ASR/强制对齐可用，或能听原声并人工逐词核对 | 口播同步；只有SRT不算通过 |
| 素材能力 | 本次需要的检索/浏览器捕获/生图/视频生成工具实际可调用 | 对应场景素材；不用的标本次不需要 |
| 输入与项目路径 | 素材可读、项目可写、实际磁盘剩余空间合理 | 读取源片/写项目与大体积成片 |

脚本自动检查基础工具、HF、技能路径、素材与工作目录；浏览器、对齐和按需素材能力由Agent继续验证。两层完成前，脚本的NEEDS_ATTENTION不能解释成“已经准备好了”。未配置凭据与服务连通性未验证分别报告。不要打印密钥、要求用户贴密钥，或把密钥写进项目/ZIP。

浏览器检查按已安装版本帮助执行，避免自动下载路径。ASR先看可调用工具和本地模型，必要时经用户同意用短样本验证；付费测试、下载模型、上传音视频前说明后执行。素材能力检查按真实计划指定：生图、视频生成、网页证据抓取都分别核对；仅本地素材则无需外部服务。能力可用仍不保证内容质量。

可将验证证据保存在工作目录 `.hf-setup/capabilities.json`，不得预填VERIFIED。示例格式：

```json
{
  "capabilities": {
    "browser": {"status":"UNVERIFIED","evidence":""},
    "word_alignment": {"status":"UNVERIFIED","evidence":""},
    "asset_acquisition": {"status":"UNVERIFIED","evidence":""}
  }
}
```

成功验证后每项记录status=VERIFIED、provider、checked_at（ISO日期）和不含秘密的实际测试证据evidence。记录仅是Agent留痕，脚本不把它当作自己执行了API/ASR测试。asset_acquisition仅在计划确定不需要联网/生成时可NOT_REQUIRED，并写理由；word_alignment仅在本次没有口播同步需求时可NOT_REQUIRED。口播视频默认必需，禁止跳过。路径/版本/provider改变立即重验，超过24小时的记录按未验证处理。

```sh
node <Skill根目录>/scripts/preflight.mjs --workspace <工作目录> --input <口播文件> --capabilities <配置记录.json> --require-assets
```

`--require-assets`用于需要额外素材能力的任务。不加时asset_acquisition不阻塞，但正式素材规划产生新依赖时必须再次检查。`--no-word-alignment`仅适用于无口播同步需求的环境诊断，不能用于普通口播制作绕过检查。`--skills-root`、`--hf-cli`可显式传入宿主实际目录/CLI文件，解决非标准安装；不能用这些参数自动写系统PATH。

## 3. 一次说明缺项，并询问配置

配置未齐时，按实际结果填写：

> 已检查这台电脑。已就绪：〔实际通过项〕。还缺/未验证：〔逐项〕，会影响〔具体步骤〕。我建议安装/配置〔工具、版本、目标路径〕；涉及〔下载大小若已知、账号、联网或费用〕。需要我帮你配置这些缺项吗？也可以指定已有安装位置，或只做当前可完成的分析。

不要原样输出占位符。问题只针对缺项，已可用不重装。未知下载大小/版本如实说明，查实际发布/安装元数据再配置，不编造数字。

| 状态 | 下一步 |
|---|---|
| 已验证齐全 | 简报“本次所需配置已就绪”，直接继续，不再问是否安装 |
| 缺失/未验证 | 给具体方案并询问；暂停依赖这些能力的制作 |
| 用户同意配置 | 按同意范围配置，保留已有配置，完成后重跑检查 |
| 用户指出已有路径 | 用新路径检查，成功后记录，不要求再安装 |
| 用户暂不配置 | 说明可完成范围；只有其选择继续分析才进入不依赖缺项的工作 |
| 账号或登录待用户处理 | 指明官方/本地设置入口，等待其操作，再验证，不索取密钥文本 |
| 安装失败 | 报真实失败原因和可执行替代方案；不无限重试、不静默换服务 |

用户这次批准配置某项后，无需每条安装命令重复询问；新增付费服务、管理员权限、上传范围或不同安装位置则重新说明变化。配置许可不替代视频任务审查。

## 4. 安装后验证及恢复

在 `.hf-setup/SETUP_REPORT.md` 记录：实际路径、通过/缺失/未验证/本次不需要、版本、计划、用户授权依据、完成验证和剩余阻塞。报告不分发，只有可公开的Skill进ZIP。不要保存账户token。

配置完成必须重跑预检及受影响能力的实际验证，不凭安装器退出码宣布成功。只有当前必需项全部通过，才能进入普通视频制作。先前视频任务已经批准且素材/参数未改变，则从中断处继续，不重新询问所有参数。

任务获批并创建项目后，以该项目为 `--workspace` 再检查一次，将完整JSON输出存为项目 `.hf-setup/preflight.json`（包含真实checked_at，不手工填通过）。写视频代码前的validate-project会拒绝缺失、超过24小时、目录不匹配或基础能力未通过的记录。能力记录可从配置位置读取，但需要复核新项目路径与版本。首次环境准备可在已有工作目录完成，不提前创建HF视频项目。

配置检查通过只代表具备执行条件；每条视频仍需音画对齐、技术检查和实际MP4导演验收。
