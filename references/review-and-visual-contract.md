# 视频、风格与任务审查

首次读取入口时阅读本文件。新项目按顺序：确认本次输入视频和处理范围 → 确认比例/时长 → 展示风格选项并取得选择 → 展示完整任务及代表画面设计 → 用户审查后生产。同一项目已明确确认的内容不重复询问。

## 选择与授权

- 历史偏好只能用于推荐；新项目仍展示完整风格列表，让用户选择或明确沿用。智能匹配也是用户可以选择的选项，不能把预选项当作回答。
- 参考视频先说明提炼出的视觉规则，再由用户确认；收到参考文件本身不代表用户接受了 Agent 的风格解读。
- “独立使用 Skill”“不要调用旧项目”“直接生成这个视频”不能自动解释成取消任务审查。任务未展示时，下一步是展示任务。
- 用户明确说“不需要任务审查，跳过确认直接制作”时尊重该指令，但记录为 `EXPLICIT_SKIP`，`task_reviewed=false`，不能伪造“已审查”。语气急迫或隔离旧项目不是放弃审查。
- 不把用户给的审查原话改写成更广泛的授权。保存引用位置和原文；无法读取会话记录时明确未核实。

## 画面必须让用户看得懂

在原任务的视觉方向里给出 2–3 个代表段落的具体画面：主对象是什么、使用什么素材、第一状态如何变为第二状态、人物何时让位/回来。它们属于同一次任务审查，不额外增加逐镜审批。只展示风格名称和配色不足以说明画面。

默认 `card_policy=NO_GENERIC_CARDS`：禁止以通用矩形、便签、标题框承载主要解释；真实网页、软件窗口、文件、图表的必要边界可以保留。用户明确选择卡片表现或卡片风格时才记为 `EXPLICIT_CARD_STYLE`。若用户同时说不要卡片，负面约束优先，保留其喜欢的色彩/材质，调整构图。

Shotcraft 的“卡”是检索条目，不是布局要求。先选真实载体和要演示的动作，再从库中取揭示、聚合、遮罩、运镜等机制。移植机制时可以去掉原演示的卡片外壳。不能因某段命中库就把原画面换成标签盒。

对于“这样、以及这样”的效果展示：先明确每个指代对应的画面，让不同例子有可辨认的主体或过程变化。不得以同一张真人静帧上的便签移动冒充两种成片效果。没有示例素材时提出本次原创演示方案，待任务审查后制作；缺证据时保留真人或说明缺口，不自动用文字卡补位。

## 审查记录

项目新增 `REVIEW_EVIDENCE.json`：

```json
{
  "mode": "REVIEWED_TASK",
  "task_file": "REVIEWED_TASK.md",
  "task_sha256": "任务文件的SHA256",
  "task_presented_ref": "会话消息ID或可追溯行号",
  "approval_ref": "用户回复消息ID或可追溯行号",
  "approval_quote": "用户实际原话",
  "style": {"id": "当前style id", "ref": "本次选择的消息位置", "quote": "用户选择原话"},
  "parameters": {"ref": "本次参数确认消息位置", "quote": "用户参数确认原话"},
  "card_policy": "NO_GENERIC_CARDS"
}
```

`REVIEWED_TASK.md`保存实际展示过的完整任务；不能将事后编写的内部故事板冒充它。任务改动后应重新核对批准范围。

显式跳过审查时 mode 为 `EXPLICIT_SKIP`，另有 `explicit_skip_review=true`，保存明确跳过审查的用户原话及引用；不需要 task_file/task_sha256/task_presented_ref，且状态里 task_reviewed 必须为 false。其余参数、风格仍应有真实依据。

校验器仅检查记录结构、文件摘要与状态一致性，不能证明 Agent 引用的对话真实或替用户判断授权语义；人工审计仍须对照会话。
