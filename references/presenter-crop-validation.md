# 人物裁切计算与核查

布局选择不等于裁切完成。矩形/圆形人物窗和分屏制作前，逐连续镜头测量完整头部（含头发、下巴），不能以五官检测框代替头部边界。检测仅供辅助；漏检、多人、侧脸时必须人工核查，不能自动把上一帧当作已验证结果。

使用随包 Node 工具（无额外模型依赖）：

```sh
node scripts/presenter-crop.mjs --input measurements.json
node scripts/presenter-crop.mjs --input crop-plan.json --validate
```

measurements.json字段：source_width/source_height为实际坐标空间尺寸，shape为RECT/CIRCLE，target_aspect为窗口宽高比（圆形为1），samples为按帧排序的 `{frame,head:[left,top,right,bottom]}`。记录测量方法、来源帧、原片身份和镜头范围，不混用4K源坐标与1080P画布坐标。命令输出到stdout，由Agent保存为项目裁切方案。

工具以已提供头部框的并集计算稳定裁切，输出crop为[x,y,width,height]。这是居中候选，不是自动识别人像、自动跟踪或构图批准。矩形采用头肩方向的安全留白；圆形进一步检查头部框四角距圆心的距离，防止矩形框没越界、头发却被圆弧切掉。圆窗安全优先，不能为机械达到头部占比68%而切头；工具50%-88%仅为宽松排错范围，不是美学目标。

若crop超出原片，显式输出SOLID_BACKGROUND填充要求；不得静默拉伸、夹紧坐标或缩减安全范围。先检查填充是否可接受；否则调整布局、分镜、窗口比例或补足来源，重新核查。头部居中不要求身体、手势也居中；手势重要时额外测量身体动作范围，当前工具不验证手势。

HEAD_CROP_PLAN.json保存各镜头输入与结果。先检查开头、中间、结尾、剪点两侧、转头/抬头极端姿态；快速运动增加采样，抽样通过不能宣称全帧通过。固定裁切不稳定时分段或提出平滑跟踪方案，不伪称现有脚本提供了跟踪。

HF实现必须使用同一crop映射到窗口尺寸，圆形/矩形蒙版独立作用，保持宽高比。制作前将实际使用的crop重新送入--validate，不能只检查早期候选。渲染后检查窗口中心与头部中心偏差、左右余量、头发/下巴、身体比例和过渡中间帧，结果记入导演报告。代码结构检查不会读取视频像素，也不能替代实际渲染比较。
