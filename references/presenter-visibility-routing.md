# 真人是否出镜：先判断价值，再选布局

保留口播音轨、原始剪点与人物素材，不等于每帧显示真人。`presenter_present`表示输入有真人素材，不表示每个Beat必须露出真人。隐藏仅关闭该段人物视觉层，不删除源文件、不切断原声、不改变词锚。

## 五种画面模式

| treatment | 何时选择 | 画面与布局 |
|---|---|---|
| FULL_FRAME | 个人判断、情绪、关系建立；人脸/动作是当前信息主体 | 真人主画面；FULL_CENTER或FULL_OFFSET_LEFT/RIGHT |
| CONTENT_ONLY | 真实录屏、作品效果、素材细节、证据阅读、场景B-roll占主导；人物没有额外价值，或挤占阅读空间 | 内容全屏、原声继续，人物布局HIDDEN；不是黑屏或静音 |
| CIRCLE_PIP | 内容主导，但表情反应/身份陪伴确有价值，且有不遮挡内容和字幕的安全角落 | 头肩圆窗；AVATAR_CIRCLE_BOTTOM_LEFT/RIGHT等按实际安全区定位 |
| RECT_PIP | 内容主导，同时必须保留手势、上半身、实际演示动作或环境 | 矩形人物小窗；RECT_PIP_BOTTOM_LEFT/RIGHT等；不得缩小整个无关房间 |
| SPLIT | 人物判断/动作与内容同样重要，两边都能读清 | SOFT_SPLIT_LEFT/RIGHT；不默认整片左真人右说明板 |

这些是导演路由与HF实现规格，不能称为已在新项目渲染验证的组件。圆形/矩形小窗不是被禁止的通用文字卡片。

## 逐段决策顺序

人物布局与B-roll是两个独立维度。真人主导仍可保留相关真实素材、局部操作与适量辅助动画；不把新增内容全屏/小窗分支当成取消原有真人B-roll的理由。逐段在VISUAL_PLAN登记 `broll_decision`，字段统一以 [画面规划](visual-planning.md) 为准，schema 2.0会检查引用和帧段；内容价值仍由实际审片判断。NONE需说明该句为何不需要补充内容；缺某项事实证据应记录缺口，不得直接把所有辅助素材设为NOT_REQUIRED。长陈述段先按实际语义审查，不按固定秒数强塞画面。动效库覆盖率与B-roll充分性分别检查。

1. 先读取并筛选用户素材，判断能否解释当前句子。素材数量多本身不是全屏理由；相关性、清晰度、来源、词锚和阅读时间才是依据。
2. 写出内容要占多少阅读空间：FULL_CANVAS / SHARED / LIGHT。效果展示、密集操作、可读证据先考虑FULL_CANVAS。
3. 判断人物当前价值：NONE / IDENTITY / GESTURE / JUDGMENT。没有额外信息且内容可用，直接CONTENT_ONLY；不要为了“像口播”再加头像。
4. 内容要全屏且人物又有不可替代的动作/判断时，拆成先后两个Beat；不把双方硬挤在一起。
5. 只有身份/反应价值且有安全区才圆窗；需要身体动作才矩形小窗；双方同等重要才分屏。位置由素材关键ROI、字幕和人头安全确定，不固定压在底部。
6. 素材不足时明确MISSING并提出补充、原生重建或暂留真人的方案。不能凭“没有素材”假报已做好全屏演示，也不以文字卡自动补位。
7. 对同一连续操作保留稳定模式，不随每个词跳布局；到个人判断或段落交接时再回真人。结束也不强制出现真人，可让作品结果承担结尾。

## 必填导演字段

每个Micro Beat新增 `presenter_visibility`，沿用同一词锚和时间线：

```json
{
  "treatment": "CONTENT_ONLY",
  "presenter_value": "NONE",
  "content_need": "FULL_CANVAS",
  "material_readiness": "READY",
  "reason": "本段需要看清实际录屏操作，人物没有额外说明价值",
  "source_audio": "PRESERVED",
  "handoff_in": "在操作词锚切入录屏，原声不断",
  "handoff_out": "操作结束后在判断句切回真人"
}
```

`material_readiness`为READY / NATIVE_PLANNED / MISSING / NOT_REQUIRED。CONTENT_ONLY至少READY或NATIVE_PLANNED；实际文件或原生实现规格在VISUAL_PLAN.json中登记。规划阶段可标MISSING，生产校验不能通过。

`presenter_direction.layout_target`必须与treatment一致。CONTENT_ONLY对应HIDDEN；其camera_action可为CUT_TO_CONTENT、CONTENT_ROI_PUSH等内容镜头动作，不要求把已隐藏的人物动起来。不因真人隐藏而取消字幕、音轨或数据来源。

## 实现和验收

- CONTENT_ONLY：隐藏人物视频视觉层或用不透明内容覆盖，显式保留独立原声音轨；避免重复播放同一音轨。技术策略以当前HF合同为准。
- 小窗：先按整段头部运动范围选择ROI，再套圆/矩形蒙版；保留发顶、头发轮廓和下巴，检查过渡中间帧及手机阅读尺寸。
- 切入全屏内容允许叙事性硬切、匹配切或遮罩接管；无需把每次交接做成人物缩小飞走。切回真人也不必从上个头像位置飞入，须符合剪辑节奏。
- 任务中逐段展示“全屏内容/真人/圆窗/矩形小窗/分屏、原因、素材、进入和退出”。这是原任务审查的一部分，不增设逐镜审批。
- 按时长汇总各模式，供诊断而非凑比例。若有明确内容展示段却全片真人可见，逐段复查原因；全片真人也可成立，但不能仅写“保持连续性”。不强制每条片子使用全部五种模式。
- 实际MP4验收：全屏段无残留真人或嵌套重复真人；原声连续；主要素材足够大；小窗无遮挡；模式切换有语义依据。结构校验不证明画面和音频已经满足这些要求。

人物小窗和分屏实施前必须读 [人物裁切计算与核查](presenter-crop-validation.md)，实际裁切使用完整头部测量与几何校验；布局字段通过不代表人像已居中。

人物窗外观采用 [已确认的圆角、描边与阴影](presenter-window-style.md)。外观批准不替代裁切和动态验收。
