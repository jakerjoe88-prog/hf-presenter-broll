# 口播 → 画面 → 素材 → 动效

## 何时使用
环境检查后先分析语义；文案、比例、时长明确后生成候选，提交任务时纳入画面设计。任务批准后才生成制作素材、读取具体TSX并实现动画。此步骤并入原任务审查，不新增逐镜头批准关卡。

每个片段写清：原话、观众应理解的一件事、现实对象、具体载体、来源与提取区域、人物位置、阅读焦点、素材缺口、连续状态与词锚、退出去向。知识判断或情绪表达可保留真人；不要求每句配图。

先建立下述上下文，再运行 `scripts/plan-visuals.mjs --input <项目>/VISUAL_PLAN.json` 查看候选。单句 `--text` 只返回 CONTEXT_REQUIRED 与探索候选，不构成制作方案。候选仍是词语召回；否定、隐喻、反例和无关同名词由Agent结合全文排除。没有合适候选时选择原生HF、真人或有理由的阅读停留，不随机凑动效。

## 全文理解和人物辅助画面（schema 2.0）

不另建论点图。将真实听审/用户提供的全文保存到分析目录的UTF-8文本，保留出处；VISUAL_PLAN的 `narration` 包含 `path`、文件 `sha256`、`topic`、`topic_span:{start,end}`。字符位置按JavaScript UTF-16索引、右开区间。摘要只作判断，不代替原文。

每个Beat增加 `semantic`：`source_span`准确引用原话；`function`为CLAIM/EVIDENCE/STEP/EXAMPLE/JUDGMENT/TRANSITION/CTA；`viewer_goal`说明希望观众理解的一件事；`topic_relation`解释画面和全文的联系。`referents`逐个记录“这样、那个、这个效果、这些效果”的原文 `phrase`、`span`、`status:EXISTING/PLANNED`、`target_beat_id`、`asset_ids`、`description`。其他有歧义的指代也人工标记。无法解析时先报告，不猜题材；待制作效果可指向已规划资产，不要求它在原片已存在。相机动画不能仅因“展示效果”就替代Codex剪辑/Skill效果。

每段增加 `broll_decision`：`mode:SUPPORT/CUTAWAY/CONTENT_TAKEOVER/NONE`，`purpose:INFORMATION/PROOF/PROCESS/COMPARISON/EMOTION/RHYTHM/IDENTITY`、`reason`。非NONE填写具体 `subject`、`action`、`expected_change`、`asset_ids`、`frames:{start,end}`、`min_read_frames`；NONE填写 `hold_subject`，只说明该段为何无需辅助，不外推到整句/整片。情绪、节奏也可有价值，不要求B-roll提供旁白以外的新事实。

人物布局另按人物路由决定。SUPPORT可保留真人，CONTENT_TAKEOVER才隐藏人物。不要把同一真人帧缩成小图视为有信息的B-roll；若需剪辑示意，应实际展示选取、删除、重排或前后变化，且主体在目标观看尺寸可辨认。无事实证明不等于无可用辅助内容。

这些字段只能验证原文、引用、资产和帧段一致，不能自动判定理解正确。Agent必须在任务里展示具体前后状态；不要自填分数冒充独立审片。先选择相关内容，再选引擎，不能为库覆盖率制造画面。

每个referent在production前还须填 `anchor_id`，指向该指代词的真实ASR词锚，并纳入本段anchor_ids。由词锚的source_range取得原片时间点；不能用别的关键词锚冒充“这样”的时间。规划阶段允许暂缺，写代码前必须补齐。

优先研究 [组合库](visual-motion-recipes.json) 的设计动作，再检查候选核心卡的适用性。六种常用组合是：证据阅读、资料到结果、前后对比、多项筛选、操作讲解、真人交接；其余六种补充步骤、数值、细节、替代、分支和焦点交接。它们是项目自行编写的设计方案，不是已迁移的12个HF组件，也不增加60卡覆盖统计的分母或分子。

## 生成前完成构图

先从原片测量人脸/头肩、字幕、操作区域，标注归一化安全区与主体区域。横屏可侧向组织；竖屏通常上下交接或短时让位，不能机械缩小横屏布局。沿用批准样稿的具象多元素风格，同时一次只有一个阅读焦点。

把缺口分为 CAPTURE（真实截图/录屏）、NATIVE（文字控件/文档结构）、GENERATE（照片级内容层）、USER_REQUIRED（只有用户能提供的实绩/私有操作）。能用现有素材完成的片段不调用生图。生图服务未验证时先走配置入口。

每次生成提示词写明：现实指代与说明目的、物件及环境、景别和视角、光源与材质、实际宽高比、主体位置、人物/字幕留白、后续镜头运动余量、输出层及需保持一致的对象。不要让模型把所有对象和文字一次画死。需要分层时分别生成背景/物件，检查边缘、透视与光源后组合；未经验证不假设支持透明输出。

可复用提示结构：
> 为[原口播]制作说明性照片内容层，现实对象是[对象]，载体是[物件/场景]。使用[景别/视角]、[光线/材质]，比例[本项目比例]。主体置于[区域]，[人物与字幕区域]保持留白，为[推近/平移/对象移动]保留[方向]余量。只生成[本层内容]；中文、数值、品牌标识、按钮与操作控件由真实素材或原生层另行添加。本图是说明素材，不表示用户真实经历或实际操作结果。

生成后检查两秒能否识别现实载体、关键对象是否正确、留白是否足够、可否按设计裁切/运动、与真实层是否统一。每张素材登记实际文件、尺寸、来源、说明/证据属性；不合格需重做或改方案，不以标题补救。

## 动效参考与优化

从设计方法中选择适合口播的动作；通过已有Apache许可的Shotcraft核心源码研究可复用实现，或自行实现HF。不要把Talkcraft的TSX、demo、纹理、音效搬入分发包。确需直接使用其工具或实现时，先处理相应授权并保留来源；不能因改成GSAP而忽略许可。

每个选择记录：参考动作、保留原因、相对参考的改动、适配风险。优化优先次序：真实载体正确 → 口播词锚 → 手机可读 → 人物/内容交接 → 跨镜头连续 → 动画细节。弹簧、模糊、景深与转场只能辅助表达。

组合不是轮番入场：按 PREPARE/BUILD/EVOLVE/HIT/RESOLVE/HOLD 组织。两次语义变化要改变对象内容、关系或阅读焦点；持续漂浮不计数。阅读停顿允许静止，需说明阅读对象与理由。

## 产物与检查

创建schema_version 2.0的 VISUAL_PLAN.json，按 [字段示例](visual-plan-example.json) 填写。示例是字段说明，不能冒充真实资产或词锚。beat_id与TARGET_DIRECTOR_DECISIONS一致；anchor_ids引用真实词锚。planning可记录待办；production模式为写代码前的检查，要求实际素材或原生实现规格、真实锚点及资产清单引用完整。PLANNED_NATIVE此时允许，但仅表示计划；写代码后必须提供命名实现对象和实际输出证据，不能直接升为成片通过。旧schema需要明确迁移，不回填旧片语义PASS。

运行 `node scripts/validate-visual-plan.mjs --input <项目>/VISUAL_PLAN.json --stage production`。它是结构检查，不证明截图真实性、素材授权、构图安全或视觉质量。最终还要在实际MP4上检查同步、ROI、人物安全、后半段演进并留逐词锚帧证据。

每个效果独立记录 DESIGN_RECIPE → SOURCE_READ（确实读过选定源码）→ HF_ADAPTED → RENDER_VERIFIED。RENDER_VERIFIED必须附实现文件、渲染文件、工具版本、检查帧与结论。不得批量把全部组合标为已适配。

## 素材充足时的内容主导

按 [人物显隐路由](presenter-visibility-routing.md)先判断每段是否需要真人。素材相关且可读、真人无额外说明价值时用CONTENT_ONLY；背景生成和素材构图无需再为不存在的人脸留空，仅保护字幕与真实ROI。缺素材先列缺口，不自动用真人或标签盒覆盖所有段落。
